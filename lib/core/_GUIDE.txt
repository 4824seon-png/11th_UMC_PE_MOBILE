[폴더] core/ — 앱 전역에서 재사용하는 설정 (Token · 네트워크 Client · 테마)
════════════════════════════════════════════════════════════════

■ 이 폴더의 역할
   - 특정 화면에 속하지 않고 앱 전체가 공유하는 설정을 둔다.

■ 넣지 않는 것
   - API별 요청 메서드 → data/services/
   - 화면 상태 → view_models/

■ 하위 폴더와 파일
   config/
     tmdb_config.dart              .env의 TMDB_ACCESS_TOKEN을 읽는 창구          [사용 중]
   network/
     tmdb_client.dart              TMDB 전용 Dio(baseUrl·Bearer 헤더·timeout 10초) [사용 중]
     tmdb_logging_interceptor.dart 요청·응답·오류 로그, Authorization 마스킹      [사용 중]
   theme/
     app_colors.dart               Figma 원본 색상 상수                          [사용 중]
     app_theme.dart                ThemeData(ColorScheme·Manrope·위젯 기본 스타일) [사용 중]

■ 동작
   Token 흐름 : .env → dotenv.load(main) → TmdbConfig.accessToken → createTmdbClient 헤더
   요청 흐름  : Service → Dio → TmdbLoggingInterceptor(onRequest) → TMDB
                → onResponse(200) 또는 onError(401·timeout) → Service
   테마 흐름  : AppColors → AppTheme.light → MaterialApp.theme → Theme.of(context)

■ 의존 관계
   사용   : flutter_dotenv, dio
   사용처 : main.dart(tmdb_config), app/movie_log_app.dart(tmdb_client, app_theme)

■ 수정할 때 주의
   - Token 원문을 print·debugPrint하지 않는다. 확인은 TmdbConfig.hasAccessToken으로.
   - Interceptor에서 원본 options.headers를 바꾸면 실제 요청의 Token도 바뀐다 → 복사본만 마스킹.
   - Interceptor 각 메서드 끝의 handler.next(...)를 빠뜨리면 요청이 멈춘다.
   - 로그는 kDebugMode에서만 등록된다 (release 빌드에서는 출력 없음).

■ 예정된 변경
   - 없음. 이후 MovieLog 자체 API Client는 network/에 별도 파일로 추가한다.
